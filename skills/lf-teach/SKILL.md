# lf-teach：讲解

## 开讲之前

1. 读 `learner/profile.md`（学习偏好）和 `learner/teaching-notes.md`（什么讲法对用户有效）。数据仓库位置用 `lf where` 查。
2. 确认知识点：`lf map <os|db>`，找到对应 concept id 和它的前置知识点。前置是“未学 / 薄弱”（`lf stats`）时，先花两分钟补前置。
3. **先问一个问题摸底**：“你现在知道 XX 是干什么的吗？”或者让用户先试一道最简单的题。根据回答决定从哪讲起，不要从定义背起。

## 讲法

- **结论先行**：第一句话说清楚这个东西解决什么问题、核心机制是什么。
- **讲为什么**：这个机制是被什么问题逼出来的（比如“为什么要两段锁”：不加约束的封锁照样会出现不可串行化的调度）。
- **例题由引擎算**：用 `lf calc` 生成过程表格，再逐行讲。例如
  `lf calc os.cpu_sched '{"procs":[...],"algo":"RR","quantum":2}'`、
  `lf calc db.decompose_3nf '{"R":"ABCDE","fds":"A->BC; CD->E; B->D; E->A"}'`。
  SQL 用 `lf sql db "<查询>" --dataset school_edge` 跑给用户看，边界数据（一门课都没选的学生、成绩为 NULL 的记录）最能说明写法差异。
- **对照教材**：导入过教材时，用 `lf book find <pack> "<术语>"` 找到页码，讲完告诉用户“教材第 N 页”，口径以教材为准（不同教材的约定见 `packs/<pack>/sources.md` 的“前人踩过的坑”）。
- **能可视化就可视化**：过程类内容（调度甘特图、页面置换表、前驱图）画成表格或图；复杂的可以做一个可交互页面。
- 一次只讲一个知识点，讲完就检查，不要连讲三个。

## 学会的标准：用户能讲回来

讲完请用户用自己的话讲一遍（“假如你要给同学讲，你会怎么说？”），或者回答一个“为什么”的追问。

- 讲对了：用 lf-quiz 出一道这个知识点的题（`lf q list --concept <id> --unseen`），真做对才算学会。
- 讲漏了或讲错了：指出缺的那一环，换一种讲法（类比、反例、画图）再来，不要重复刚才的话。

## 讲完之后

1. 某种讲法明显奏效（用户讲回来很准，或者马上做对了题），追加一行到 `learner/teaching-notes.md`：
   `- [system] 2026-10-24 os.vm.replace：先让用户手算 OPT 再讲 LRU，比直接讲 LRU 快`。
   讲法没效果也记一行，标明“无效”。人写的 `[human]` 条目不要改。
2. 记一条学习摘要：`lf note "讲了 os.vm.replace；能讲回 LRU 的更新规则；CLOCK 还没讲"`。

## 不要做

- 不要直接把题库答案当讲解念出来。
- 不要读 `holdout/`，不要用盲测题当例题。
- 计算过程不心算，全部来自 `lf calc`。
