# lf-review：现在适合复习什么

## 原则

- **不催。** 不设提醒、不建定时任务、不说“你已经 N 天没学了”。用户打开时才给建议。
- **节奏是用户定的**（`learnforge.yaml` 里的 `review_every_days`），系统只决定“这次复习什么”。用户要改节奏就改那个文件。
- 建议必须带理由，理由来自 `lf today` 的输出，不自己编。

## 流程

有 learnforge MCP 工具时，第 1 步改为调用 `lf_dashboard`（支持界面的宿主会显示复习面板，用户可以直接点“练这几题”），其余不变。

1. 用户说了时间就用用户的时间，没说就用默认值：

   ```bash
   lf today --minutes 60
   lf today --pack db --minutes 45
   ```

2. 把计划用几行讲给用户：每一项是什么、为什么排在这（遗忘程度、考试权重、未订正的错题）、大概多少分钟。原样保留 `lf today` 给的题号。
   - 输出里提示“还没设考试日期”时，问用户一次考试日期，拿到后 `lf pack os set exam_date 2027-01-10`。
   - 有“专项练习”时放在最前面说。
   - 考前两周会出现“覆盖缺口”，提醒用户这些考点还没练或最弱。
3. 用户同意后逐项执行：
   - `[新学]` → 按 lf-teach 讲，再按 lf-quiz 出题。
   - `[订正]` → 先重做错题（列在最前的题号就是未订正的错题），再做一道同类新题。
   - `[复习]` → 直接做题（lf-quiz），做对就过，做错再讲。
4. 结束时：

   ```bash
   lf stats --pack os
   lf note "复习了 …；错因 …；下次 …"
   ```

   用两三句话告诉用户这次的变化（哪些知识点从“薄弱”变成“不稳”或“还行”），以及按现在的节奏下次大概该看什么。

## 进度与预测分

用户问“我准备得怎么样了”：跑 `lf stats`，按章说掌握情况和错因分布。`预测分` 是粗估（未学的知识点按 25% 计），明确告诉用户这只是参考，真正的标准是盲测卷（`lf holdout run <pack>`，由用户本人在终端里做，你不参与、不看题）。

## 不要做

- 不要读 `holdout/` 目录。
- 不要改 `learner/mastery.json`，它由引擎从作答记录重算。
- 不要擅自改复习节奏或考试权重。
